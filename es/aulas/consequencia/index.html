Clase 3 · 18 min

Una acción con consecuencias pide a una persona: confirmación y consequentialHint

Reservar, cancelar, pagar, borrar. El agente puede elegir la tool equivocada, entender mal la descripción u obedecer a un texto plantado. La spec de WebMCP responde con consequentialHint, para que el cliente exija confirmación. En esta clase pones la anotación y la confirmación del propio sitio, y compruebas que rechazar no cambia nada.

Comenzar la clase

En esta clase vas a

  1. 1Intención mal descrita: el caso finalizeCart de la spec
  2. 2consequentialHint (señal para el cliente) y confirmación del sitio (tu traba)
  3. 3La prueba que rechaza y verifica que nada cambió
  4. 4El límite: un agente que opera la pantalla también hace clic en el botón

Objetivo: poner consequentialHint y una confirmación con objetivo y efecto en toda tool que cambie algo, y comprobar que rechazar no cambia nada.

01 · Del pedido al efecto, con una persona en medio

Haz clic en cada etapa.

Haz clic en cada bloque del diagrama para ver qué hace.

La anotación es para el cliente; la confirmación es tuya. Una no sustituye a la otra.

02 · Una confirmación que protege

1. Objetivo y efecto

La pregunta dice qué, de quién y qué pasa después. "¿Estás seguro?" no sirve: la persona no sabe qué está aprobando.

2. Atada a la llamada

Una pregunta por llamada, con los argumentos de esa llamada. Si el objetivo cambia, es otra pregunta. Nunca un "sí" que valga para las siguientes.

3. Un nombre que dice el efecto

La spec muestra finalizeCart: el agente creyó que solo cerraba el carrito para verlo, y la tool compró (§6.3.2.3). Nombre y descripción dicen el efecto: comprar_carrinho, "cobra la tarjeta guardada".

4. El límite

El diálogo está en la página, y un agente que opera la pantalla también puede hacer clic en Confirmar. El propio checar.mjs hace clic, como lo haría un agente. Para una acción de alto valor, pide algo que el agente no tiene: la contraseña otra vez o un código enviado a la persona.

03 · El segundo agujero: cancelar sin preguntar

Edita cancelar_agendamento en kit/pagina/ferramentas.mjs como en el fragmento y ejecuta el verificador. La versión lista está en kit/solucao/aula3/.

Fragmento · kit/solucao/aula3/ferramentas.mjs
      annotations: { consequentialHint: true },              // clase 3: avisa que la acción tiene consecuencias
      execute: util(async ({ codigo }, { signal }) => {
        const ag = agenda.agendamentos().find(a => a.codigo === codigo);
        if (!ag) throw new Error(`agendamento não encontrado: ${codigo}`);
        // la pregunta dice el objetivo y el efecto completos; cancelar la ejecución (signal) vale como "no"
        const ok = await ui.pedirConfirmacao(`Cancelar o agendamento ${ag.codigo} (${ag.id}, ${ag.nome})? A vaga volta para a agenda.`, signal);
        if (!ok) return { cancelado: false, motivo: 'a pessoa recusou na tela' };
        agenda.cancelar(codigo);
        ui.atualizar();
        return { cancelado: true, agendamento: ag };
      })
